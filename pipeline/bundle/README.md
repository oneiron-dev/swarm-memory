# pipeline/bundle: the static data bundle

`build_bundle.py` turns the pipeline's work area on Arch (`meta/`, `slice/`, `tags/`, `summaries/`) into the served bundle `bundle/data/` described in `docs/schema.md` section 4. `validate_bundle.py` checks a built bundle against that contract.

## Run (Arch)

```bash
W=/home/lexi/calc-nvme/hackathon-20261004
B=/home/lexi/calc-nvme/wt/swarm-serve/pipeline/bundle
$W/venv-bundle/bin/python $B/human_names.py      # once: meta/human_names.json (redaction list, never served)
# once, after a build: meta/extra_human_ids.json (usernames and handles of humans; see "Extra human ids" below)
$W/venv-bundle/bin/python $B/human_ids.py candidates --data $W/bundle/data   # or a scratch build with --top-entities 2600
$W/venv-bundle/bin/python $B/human_ids.py classify --prime-agent /home/lexi/.local/bin/prime-agent
$W/venv-bundle/bin/python $B/human_ids.py scan && $W/venv-bundle/bin/python $B/human_ids.py hits
$W/venv-bundle/bin/python $B/human_ids.py write --review $W/human_ids/review.txt
$W/venv-bundle/bin/python $B/build_bundle.py     # writes $W/bundle/data/ and $W/bundle/BUILD.json
$W/venv-bundle/bin/python $B/validate_bundle.py  # checks $W/bundle/data/; exit 1 on any ERROR
```

A rebuild is one command: about 30 seconds on the full slice without tags, about 5 minutes with tags and the identifier rules (validation included), under 1.3 GB of RAM. Each build writes an immutable generation `bundle/gen/<UTC stamp>-<pid>/`, validates it, and only then points `bundle/data` (a symlink) at it with one rename, so the served path always resolves to a complete, validated bundle. The previous generation is kept (roll back by pointing the link at it); older ones are removed. A build that fails validation exits 1, leaves the link unchanged and keeps the rejected build in `bundle/failed/` (`--no-validate` skips the check). A missing or unreadable `meta/human_names.json`, `meta/extra_human_ids.json`, `meta/extra_human_rules.json` or `meta/context_handles.json` stops the build before anything is written. Any input except `meta/` may be missing or partial (a file still being appended is fine): the matching parts are then empty but valid. Venv: `uv venv -p 3.12 venv-bundle && uv pip install -r requirements.txt` (`wordfreq` is required for the name rules below; `orjson` is optional, without it the stdlib `json` is used).

## Inputs

| path | used for |
|---|---|
| `meta/agents.json`, `rooms.json`, `days.json`, `village_goals.json`, `agent_goals.json` | agents, rooms, days, goals |
| `meta/summaries_index.json` | type and day of each AI Digest summary (village summaries use `daily`) |
| `meta/human_names.json` | human display names to redact (pipeline-internal; required) |
| `meta/extra_human_ids.json` | usernames, handles and email-like ids of humans that are no display name (pipeline-internal; required, `[]` when none) |
| `meta/context_handles.json` | handles of humans that are also English words, cut only in handle context (pipeline-internal; required, `[]` when none) |
| `meta/extra_human_rules.json` | exact-case names, ids, per-location tokens, dropped entities, profile allowlist (pipeline-internal; required, `{}` when none) |
| `slice/slice-<kind>.jsonl` | counts, interactions, memory rows, quoted text (schema section 1) |
| `tags/tags-<kind>.jsonl`, optional `tags/LABELS.json` | entities, mention series, mood, memory entity sets (section 2) |
| `summaries/*.jsonl` | agent and room summaries (section 3) |
| `tags/tags-summaries.jsonl`, optional | oneiroNER spans over summary `text` (same ids as the summaries); PERSON spans are redacted |
| `findings/findings.json`, optional | cited findings (schema v1.2.4); written to `data/findings.json` |
| `book/days.jsonl`, `chapters.jsonl`, `hooks.jsonl`, `pairs.jsonl`, `adherence.jsonl`, `rewrites.jsonl`, optional | the book's texts from `pipeline/book` (schema v1.3); written to `data/book.json` and `data/adherence/<agent>.json` |

## Outputs

`bundle/data/` (served, schema v1.3): `bundle.json`, optional `findings.json`, optional `book.json` and `adherence/<agent>.json` (when `book/days.jsonl` exists), optional `pairs.json` (when `book/pairs.jsonl` exists too), `talk/<agent>.json`, `entities/<slug>.json`, `summaries/agent/<agent>.json`, `summaries/room/<room>.json`, `summaries/village/<day>.json`, `memory/<agent>.json`, `sources/<day>.json`. Caps (checked by the validator): `bundle.json` under 3 MB, any on-demand file under 2 MB, all of `data/` under 100 MB. Snippets are cut at 600 characters.
`bundle/BUILD.json` (timings, counts, warnings) and `bundle/redaction_names.json` (the entries in use and the rows and summaries redacted without tags) stay beside `data/` and are never served.

## What the bundler decides

- **Span snap (word-v1).** Tags on Arch stay raw; the build snaps a copy (`bundle/.tags-snapped/`, never served) while it streams the slice. A span whose start or end falls inside an alphanumeric run is widened to the word edges (surrounding whitespace trimmed); same-label spans that then touch or overlap are merged; spans with no letter or digit are dropped. `manifest.tagger.snap = "word-v1"`; the counts (`spans_in`, `snapped`, `merged`, `dropped`) are in `BUILD.json` under `counts.snap`.
- **Agent names first.** A span whose text is an agent's display name or slug (`o3`, `GPT-4o`, `gpt-4o`) is always kept, whatever its label or length. It is keyed to that agent (one entity per label and agent, `"agent": "<id>"` on the light record), counts as a mention edge, and is never redacted.
- **Entities.** Tag spans grouped by (label, folded text: lowercase, whitespace folded, leading "the " dropped). Scrub-marker spans are dropped, and so are spans that overlap an email address or uuid in the slice text, even a part of one such as the mailbox (an id is built from the text; counted as `counts.snap.dropped_email_or_uuid`); an entity whose text would change under redaction gets an opaque id `e:x<hash>`. A PERSON span is an entity only when it names an agent. Top 2,000 by count as light records in `bundle.json`; per-agent counts and the daily timeline in `entities/<slug>.json` (slug = id without `e:`, `[a-z0-9-]`, unique). If `bundle.json` would still pass its budget (`--budget`, default 2.9 MB), the list is trimmed from the bottom. Up to 5 examples per entity, spread over its active days and preferring readable kinds over thinking and memory.
- **Interactions.** `mention`: a chat, session or Claude Code text names another agent (display name or slug, any case, word-bounded; `Model 4` never matches inside `Model 4.1`), or carries a tag span whose text is an agent name; one count per message and target. `reply`: the next chat message in the same room within 10 minutes from a different speaker. All humans are the single node `human`.
- **Memory drift.** The last memory of each agent per day, its set of bundle entities, `added`, `dropped`, `jaccard_prev` (null for the first memory or two empty sets).
- **Redaction of served text.** Sources, memory excerpts, agent, room and AI Digest summaries, findings, entity texts and goals pass through the same filter, and a final sweep runs it over every served string once more (ids and refs excepted; `counts.redaction.sweep` in `BUILD.json` should stay 0). Names from `meta/human_names.json` and PERSON spans that are not agents become `[human]`; email addresses become `[email]` and uuids `[id]`. The output is checked again, since a cut can join text into a new name. Cuts happen at word boundaries. Over-redaction is the chosen failure mode. Matches per rule are in `BUILD.json` under `counts.redaction`.
  - **Name list.** Every name on `meta/human_names.json` is used and never dropped, except names under 3 letters ("B" alone would hit tens of thousands of words) and names made only of `STOP_WORDS` (greetings, generic handles, platforms, model families), agent-name words and digits. Human names match on ordinary word boundaries ("vexa-led", "vexa.example"); the model-version boundary rule ("Model 4" never inside "Model 4.1") is for agent names only. Handles (a digit or `_`) and names with a word that is not a common English word (`wordfreq` zipf under 3.5, not in `STOP_WORDS` or `NAME_WORDS`) match in any case, everywhere: a display name typed in lowercase is copied in lowercase. Several-word names of common words match when capitalized or in their listed form. One-word names that are common words ("Will", "Time") are redacted where oneiroNER tagged that occurrence PERSON, in any case, in every tagged text (sources, memory, AI Digest texts, summaries once `tags-summaries.jsonl` exists); in untagged text (goals, findings, rows without tags) their capitalized occurrences that are not sentence-initial are redacted. The first and last word of a two- or three-word Title Case name are added as one-word names. Counts per rule are in `BUILD.json` under `counts.human_names`; the untagged rows and summaries are listed in `redaction_names.json` for the validator.
  - **PERSON spans** are widened to whole words, because the tagger sometimes marks part of a word; spans with fewer than 2 letters, and spans made only of generic words, agent-name words and digits ("a human", "Opus 4.5"), are kept. Summary text uses the spans from `tags/tags-summaries.jsonl` (word-snapped at build time) when that file exists.
  - **Extra human ids.** Ids on `meta/extra_human_ids.json` match in any case at letter-or-digit boundaries, so also inside `@x`, `x-dev`, `x_y`, URLs and paths; the parts of an id may be joined by any 1 to 3 separators (`a-b` also matches `a b`, `a_b`, `a/b`). An entity whose text matches one (or any rule below) is dropped like a listed name: no id, no page, no memory entity. Counts: `counts.redaction["name:extra"]`, `counts.extra_human_ids`.
  - **@handles.** An `@handle` becomes `[human]` unless it is exactly an agent's display name or slug, in any case and with any of ` -._` between its words (`@o9`, `@Agent Alpha`, `@agent-alpha`, `@agent_alpha`), an agent family word on `AGENT_FAMILY_HANDLES` (`@claude`, `@opus`, `@gemini`, `@o3`, ...; the whole handle, any case), or a public organisation account on `PUBLIC_HANDLES` (AI Digest / AI Village, AI labs, charities). Other partial names and lookalikes go: `@alpha`, `@AgentAlpha`, `@model12345`, `@agentalpha_9`, `@aidigest_fan`, `@12345`, `@notes.md`, `@everyone`. A cut at 600 or 400 characters never splits `@Agent Alpha` (its first word alone would read as a handle). The one code exemption: a well-known code at-word on the fixed `CODE_AT_WORDS` list (`@media`, `@keyframes`, `@dataclass`, `@app.route`, `@types`, ...) as the whole handle and only inside a `` `backtick` `` span (to the end of its line when unclosed) or a fenced block (to the end of the text when unclosed); outside code it is redacted like any handle. Count: `name:at`.
  - **Names next to `[human]`.** Capitalized words right after a `[human]` token or right before it (`Firstname [human]`), joined by a whitespace run (spaces, tabs, at most one newline) or `/`, join the token: the run becomes one `[human]`. One nickname may stand between, on either side: parenthesised or in straight or curly, single or double quotes (`[human] ("x") Surname`, `[human] 'x' Surname`, `Surname ("x") [human]`); the word next to a nickname needs only to be capitalized and no agent name, stop word or role, and at most 2 words go with a nickname (`NICK_WORDS`). Agent names, stop words, roles and titles never join. The Title Case or ALL-CAPS word right after the token on the same line joins however common (`[human] Zorn's`, `[human] ZORN.`; not an acronym such as `API`), and so does a surname particle with its name (`[human] van Zorn`), unless another such word follows (a heading: `[human] Moon Mission` stays). Every other word must also not be all-caps, carry a digit or a second capital, or be a common English word (zipf 4.0 or more, except frequent family names on `SURNAMES`), and before the token it must not start a sentence ("[human] Moon Mission" and "Yesterday [human]" stay; `[human] ("x") Moon Mission Celebration` keeps "Mission Celebration"). Count: `name:neighbour`.
  - **Identifier rules.** Beyond names, these go everywhere (also in the validator and the final sweep), each with its token: percent-encoded emails (`a%40b.org`) become `[email]`; phone numbers (international, `(555) 201-7788`, `555-201-7788`, ten digits with a NANP (US/Canada) area code, so a unix time stays) and order, tracking, customer, user, transaction and receipt ids (a token with 5+ digits, at least 40% digits and no date, within 40 characters after one of those words) become `[id]`; the account segment of a profile URL (`github.com/<user>`, GitLab, X/Twitter, `linkedin.com/in/`, Bluesky, Reddit `u/`, dev.to, Substack/Medium `@`, scheduling links, `<user>.github.io`, `<user>.substack.com`) becomes `[human]` and the host stays, unless it is a site route or on the allowlist (`PROFILE_ALLOW` plus the rule file's `profile_allow`: org, agent and project accounts); the operand of `from:`, `to:`, `cc:`, `bcc:`, `author:`, `user:`, `sender:` in a person search (a search, inbox, mail or message word before it on its line, or a mail-search operator such as `in:` or `subject:` on the line) and outside code (`Convert from:JSON to:YAML` stays); usernames written without an @ (3+ letters ending in 2+ digits, not all capitals) within 50 characters after or 30 before a reader, viewer, customer, contributor, author, buyer, donor, volunteer, recipient, follower, subscriber, commenter, correspondent or player word, or inside a quoted search query; the name in a salutation ("Hi X,", "Dear X Y", "Thanks X for"; not "Hi everyone", "Dear Team" or an agent); the name after an academic or medical title ("Dr. X", "Professor X Y"); ALL-CAPS two- or three-word names within 60 characters after a ship-to, deliver-to, bill-to, sold-to, shipping address/name/label, recipient, addressee, buyer or customer (name) word, every word a name-like 2-15 letters and none a tech, protocol or status acronym (`CAPS_TECH`, `CAPS_KEEP`: "Customers used HTTP GET" stays). Counts: `name:email_pct`, `name:phone`, `name:order`, `name:profile`, `name:query`, `name:cue_user`, `name:salutation`, `name:title_name`, `name:caps_name`.
  - **Context handles** (`meta/context_handles.json`, required, Arch only): a handle that is also an English word ("pebble") becomes `[human]` only in handle context: right after `@` or `u/`, inside a backtick span, or within three words (either side) of user, username, handle, creator, trader, bettor, buyer, commenter, poster, "replied to" or "reply to"; "a pebble path" stays. Count: `name:context`.
  - **Common-word names acting as people.** A one-word listed name that is a common word (word-cap) or a stop word ("Max"), written capitalized or in capitals, goes in every text when a person verb follows it (`MAX posted`, `Kit replied`: posted, replied, commented, wrote, said, asked, sent, shared, liked, emailed, messaged, joined, subscribed, mentioned, responded, thanked, suggested, requested, offered, tweeted, answered, reacted, followed, signed up) or when it is the value of a people label (`External participants: **Zero**`). Count: `name:acts`.
  - **Cut mail addresses.** A mailbox whose domain lost its dot and TLD right after a mail header label (`To: ada@zornmail.`, also `From:`, `Cc:`, `Bcc:`, `Reply-To:`) becomes `[email]`; `react@18` and `checkout@v4` stay. Count: `name:email_cut`.
  - **Chess games and accounts.** A game page shows both players' usernames, so a lichess.org path segment of 8 to 12 letters and digits that is no site route (`lichess.org/<game id>`, also a study id) and the game id in a chess.com `/game/...` link become `[id]`; the account after `lichess.org/@/` or `chess.com/member/` becomes `[human]` unless it is an agent or allowlisted. A bare 8-character id in parentheses right after a `[human]` chip (`[human] (wnZTu3Q9)`) becomes `[id]` when it reads as an id (a digit, or capitals beyond a Title Case or ALL-CAPS word); `[human] (designer)` stays. The validator flags the same shapes. Counts: `name:game_id`, `name:chip_id` (the chip rule fires in the recheck, after the name became a chip: `recheck`).
  - **URL tokens.** A path or query segment of 24 or more letters, digits, `_` or `-` with both cases in any URL (a capability link, a document, channel or account id) becomes `[id]`; the host and the rest of the path stay, and lowercase hashes stay. Hosts kept as they are: `docs.google.com`, `drive.google.com`, `youtube.com` (and its subdomains) and `youtu.be` (public documents and videos the agents made; their ids identify no person). In a lichess.org path a sign-up confirmation or magic-link token (16+ base64-like characters) becomes `[id]` too. Count: `name:url_token`.
  - **Rule file** (`meta/extra_human_rules.json`, required, Arch only): `exact` names matched only in their exact case (a name that is also a common word: "Moss" goes, "moss" stays), `cap` names matched where capitalized and not starting a sentence, in every text, tagged or not ("an exchange with Fern" goes, "Fern starts" and "fern" stay), `ids` cut as `[id]` (order numbers, phones), `at` tokens cut only at one served file and JSON path (a common word that names a person in one row only; the cut text is fitted to its 600 or 400 character cap again), `drop_entities` (folded entity keys never served), `profile_allow`, and `keep`: public figures (full names, surnames, personal domains) matched in any case; a match or PERSON span that lies entirely inside one is dropped, but a match that reaches beyond it (`@zzq-quill` around a kept "Quill") and any match of an explicit private id (extra id, `exact`, `ids`, `cap`) always stays. An entity whose text matches any rule, in its own or title case, or is on the drop list is dropped whatever its label: no id, no page, no memory entity. Counts: `name:exact`, `name:extra_id`, `name:at_rule` (`at_rule_unresolved` when its path is gone), `rules_*` under `counts.human_names`.
  - **AI Digest markup.** Daily texts lose their wrapper tags (`<list_of_chronological_events>`, `<narrative_summary>`, `<top_moments>`, `<takeaways>`, `<blurb>` and any line holding only a tag); spans shift with the text.
- **Human-authored rows.** A row with `speaker == "human"` counts for the `human` node everywhere, whatever its `agent` field says.
- **Findings.** Each cite's `day` is set to its ref's day; a cite whose ref is not in the slice is dropped; every cited ref gets its snippet in `sources/<day>.json`, and the validator checks that each one resolves.
- **Citations.** A summary or finding cite whose ref is not in the slice is dropped, and so is its `[n]` marker (with the space before it), so served text never carries an unbound marker.
- **Validator.** Besides shapes, references and sizes: the human-name check reads the FULL `meta/human_names.json` and `meta/extra_human_ids.json` under the same rules and the builder's own matcher (extra ids, @handles and names next to `[human]` included; each error line counts the hits per rule) over every JSON string value and object key (common-word names are checked in the untagged strings the build lists); entity ids and every served file path (an entity page that nothing lists included) carry no listed name, extra id or @handle; every `[n]` is bound to a cite, source text is a string and its agent and room exist, and the summary records add up to `manifest.counts.summaries`.

- **Book (schema v1.3).** Chapters come from `book_chapters` (a day joins the chapter whose goal equals its `village_goal`; a day without one joins the chapter of the day before). Every day and chapter is listed whether or not a text is cached (`text` and `title` are then null); a cached chapter whose goal no longer matches is not used. A text or title first takes its accepted rewordings from `book/rewrites.jsonl` (each keyed by the hash of the exact text it replaces; `counts.book.rewrites_applied`). Texts, titles and notes are new text without oneiroNER spans, so they get the untagged rules (capitalized common-word names included) and the validator checks them as untagged; `book.py rephrase` rewords sentences where that would cut a plain word; a cite whose ref has no source is dropped with its `[n]`. A chapter's `hook`, `beats` and `figure` (book.json `swarm-book/1.1`) come from `book/hooks.jsonl`, the line made from the cached chapter text (keyed by its hash); each takes its accepted rewordings (`hook`, `beat:<i>`, `figure_label`), is redacted, beat markers without a kept cite are cut and the beat's `cites` are read from its text, and each is served only when it still passes `hook_problem`, `beats_problem` or `figure_problem` beside the served text (else null; `counts.book.hooks_dropped`, `beats_dropped`, `figures_dropped`). A chapter's `stage` (book.json `swarm-book/1.2`, on every chapter, null or an object) comes from `book/stage.jsonl`, the line made from the cached chapter text and its cached beats (keyed by both hashes); a label the redaction would change is served as null (`counts.book.stage_labels_dropped`), and the stage is served only when it passes `stage_problem` beside the served text, beats and active agents (else null; `stage_dropped`; a chapter whose line says null counts as `stage_null`). An adherence score outside `on|partly|off|idle` or missing is served as null. `talk/<agent>.json` sums the interaction edges of both directions per day and keeps the top 5 partners (`human` included). Counts are under `counts.book` in `BUILD.json`. The validator checks shapes, that the chapters cover every day once, that every `[n]` has a cite and every cite's ref is in `sources/<day>.json`, `book.json` under 1 MB wherever it is present (a present `null` is an error), runs the same three checks on every served hook, beats and figure (and refuses one beside a null text), wants a `stage` key on every chapter and runs `stage_problem` on every served stage (kinds from the catalogue, beat indexes within the served beats, agent ids among the chapter's `agents`, labels of at most 3 words with no brackets or quotes and no number the text lacks; none beside a null text), and runs the common-word check over every book text, title, goal, hook, beat, figure label, stage label and note.
- **Pairs (`swarm-pairs/1`).** `pairs.json` is `{"schema", "generated", "model", "days": {"<day>": [{"a", "b", "w", "text", "cites"}]}}`: for every bundle day, the day's three strongest talking pairs exactly as the book page picks them (`day_pairs` over the served interaction edges: both directions folded, the day's weight `w` summed, a stable sort, the first three; `a` < `b`, `human` included). Each sentence comes from `book/pairs.jsonl` (per pair the last line with a text), takes its accepted rewordings (unit `pair:<day>:<a>:<b>`, field `text`), is redacted, and is served only when it passes `pair_problem` (8 to 16 words, a full stop at the end, no square brackets so no chip, no quotation, no dash, no question) and keeps at least one cite whose row has a source (cites are `{"n", "ref", "day"}` like book.json's); else `text` null and `cites` []. Counts: `counts.book.pairs`, `pairs_with_text`, `pairs_dropped`. The validator checks the schema, every bundle day present, the pairs equal to `day_pairs` of the served edges, `a` and `b` two agent ids, `w` > 0, every text against `pair_problem` with non-empty cites in `kind:id` form whose refs are in `sources/<day>.json`, and runs the common-word check over every pair text.

## Tests

`python3 -m unittest discover -s pipeline/bundle/tests` builds a bundle from synthetic fixtures (`tests/make_fixtures.py`: fake agents, rooms, people, projects, findings and a small word-frequency table in place of `wordfreq`) and validates it. `tests/expected/data/` is that fixture bundle, for the frontend to develop against.

## Extra human ids (`human_ids.py`)

A person can appear by a username or handle that is no display name. `human_ids.py` finds them; everything it writes stays in `$W/human_ids/` and `meta/` on Arch and is never committed or served.

1. `candidates`: the entity surfaces of a built bundle (text, label, count, aliases, one example of up to 200 characters). Use a scratch build with `--top-entities 2600 --budget 9000000` so the entities that move up when some are dropped are covered too.
2. `classify`: gpt-5.6-luna through prime-agent (`--provider cpa-r --no-tools`, items on stdin, batches of 100, stops if `responseModel` is not `gpt-5.6-luna`) marks each surface `human_individual` or `other`. Agent-name entities are not sent. A reply whose `n_items` is not the batch size, that is not valid JSON, or whose hits name no item of the batch is retried (`--attempts`, default 4) and never saved; a batch left without a complete reply makes the step exit 1. Runs resume: saved batches that are incomplete (from older runs) are sent again. A second run with `--thinking medium --work <dir>` can be merged with `hits --merge <dir>` (`hits` takes the union of every saved reply).
3. `scan`: handle-shaped tokens (`@word`, `word-dev`, `word123`, `word_word`) near human words in served text.
4. `hits`: one numbered list (`h<n>` classifier hits, `s<n>` scan candidates) for review.
5. `write --review <file>`: one line per decision, `h<n> accept|reject <reason>`, or `+ accept <id> | <reason>` for an id found in review. Every classifier hit needs a verdict. Writes `meta/extra_human_ids.json`.
6. `redteam --leaks <jsonl> --review <file>`: folds a privacy red-team's leak rows (`{file, ref_or_path, identifier, kind, context, confidence}`; high and medium) into `meta/extra_human_ids.json` and `meta/extra_human_rules.json`. By default a token is an any-case extra id (a URL gives its account, subdomain or personal-domain label; a phone or number gives an `ids` entry; an encoded email is left to its rule). The review file names the exceptions, one `<exact|cap|at|drop|reject> <identifier> | <reason>` per line; `--keep <file>` lists public figures to keep visible (written to the rule file's `keep`), `--add <id>` adds a reviewed id. Rows may give `$[...]` paths or RFC 6901 pointers. Profile accounts on the served bundle that the red-team did not flag go on `profile_allow`. Prints counts only.

Data: AI Digest / AI Village. Research use only.
